## 2024-10-25 - Prevent Full Widget Tree Rebuild on Status Polling
**Learning:** In Flutter, updating a variable via `setState` triggers a rebuild of the entire `build` method, including all child widgets. When handling frequent background polling events (like HRMIS location injection status checking), updating the status overlay state triggered a full application rebuild containing heavy components like `InAppWebView` and complex layout structures leading to unneeded compute cycles and jank.
**Action:** Always prefer isolated state updates for frequently changing UI strings that are displayed in overlays or specific panels. Extract the status string into a `ValueNotifier<String>`, pass it to the `ValueListenableBuilder` in the overlay UI, and mutate `.value` directly to avoid global rebuilds.
